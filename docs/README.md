# Geo / ASN кодер

Мелкий справочник вне горячего пути. На вход — IP или CIDR, на выход —
вхождение в country и вхождение в ASN. Не инспектор: ничего не решает
по запросу, только кодирует адрес.

Один метод `Lookup` на gRPC и те же данные по HTTP. Точный адрес отвечает
на вопрос «кто это»: **все** анонсы, накрывающие адрес, от самого узкого к
самому широкому, и эффективный — тот, чей кусок под адресом остался после
вычета более узких, — первым. Маска отвечает на вопрос «кто здесь есть»:
каждая система один раз, списки без повторов.

Кодер отдаёт факты, не политику. Что из накрывающих анонсов писать в набор
при бане — самый узкий, все или систему целиком, — решает профиль
инспектора; кодер лишь не теряет ничего из того, что знает.

`POST /lookup/batch` — тот же `Lookup`, но на список адресов одним походом:
UX копит карточки в кадре и шлёт один запрос вместо одного на строку
таблицы. Порядок ответа совпадает со входом, битый адрес размечает только
свой элемент — `error`, а не 400 на всю пачку. Потолок — `MaxBatch` (500),
выше — `400 too_many_addrs`.

```
geo/
├── testdata/            учебные выгрузки: ru, us, jp и несколько ASN
├── proto/               Lookup
├── cmd/geo/             процесс
└── internal/
    ├── table/           интервалы и двоичный поиск
    ├── load/            каталог, TSV, MaxMind DB
    ├── store/           снапшот в памяти, источник на вид и опрос диска
    ├── fetch/           копии выгрузок из панели: policy/geo, скачивание, подмена
    ├── mmdbtest/        сборщик MaxMind DB для тестов
    ├── lookup/          разбор addr и сбор списков
    ├── httpapi/         GET|POST /lookup
    └── grpcapi/         rpc Lookup
```

## Ответ

```json
{
  "gen": 17,
  "countries": [{"code": "us", "name": "United States"}],
  "asns": [
    {"asn": 15169, "name": "GOOGLE", "prefix": "8.8.8.0/24",
     "effective": true, "range": {"start": "8.8.8.0", "end": "8.8.8.255"}},
    {"asn": 3356,  "name": "LEVEL3", "prefix": "8.0.0.0/9"}
  ]
}
```

| Поле | Что |
| --- | --- |
| `gen` | поколение снимка кодера; сменилось — кэши клиентов устарели |
| `prefix` | анонс, накрывший адрес |
| `effective` | этот анонс побеждает под адресом; ровно у одной строки ответа на адрес |
| `range` | эффективный кусок под адресом, включительно; только у эффективной строки |
| `prefixes` | состав системы целиком — все её анонсы; только по просьбе `expand=asn` (`expand_asn` в gRPC) |

Одна сеть у нескольких систем (MOAS) — по строке на систему с одним и тем
же `prefix`. Ответ на диапазон несёт `asn`, `name`, `prefix` — как раньше,
без `effective` и `range`. Пачка `/lookup/batch` состава не даёт: она для
таблиц, не для бана.

Состав крупной системы — десятки тысяч префиксов; ни кодер, ни клиент его
не режут: читать целиком, держать в памяти, сбрасывать по `gen`. У gRPC
это значит потолок входящего сообщения у клиента выше умолчания в 4 МБ.

Неизвестный адрес — пустые списки, не ошибка. Битый вход — `400` /
`InvalidArgument`.

## Сколько стоит вопрос

Ответ кодера — двоичный поиск в памяти, и стоит он **доли миллисекунды**.
Замер на стенде, 2000 вызовов по gRPC из соседнего контейнера:

| Что | p50 | p95 | p99 | max |
| --- | --- | --- | --- | --- |
| Вызов на готовом канале | 0,22 мс | 0,34 мс | 0,50 мс | 1,2 мс |
| То же с составом системы (`expand_asn`) | 0,23 мс | 0,35 мс | 0,47 мс | 1,1 мс |
| Первый вызов на свежем канале | 6,7 мс | 8,4 мс | **3,1 с** | **8,0 с** |

Секунды в последней строке — не кодер. Это DNS: клиент grpc-go перед первым
вызовом спрашивает запись `TXT _grpc_config.<host>` (сервис-конфиг в DNS).
В контуре такой записи нет, встроенный DNS Docker отвечает на неё 5–25 мс,
а изредка — `server misbehaving` через 8 с. Отсюда и `<X>_GEO_UNAVAILABLE`
на первой же записи подсети при бюджете в 100 мс.

Поэтому клиент кодера (`internal/netinfo` у инспекторов) снимает два
умолчания grpc-go и заводит соединение заранее:

| Мера | Зачем |
| --- | --- |
| `WithDisableServiceConfig()` | убирает поход за `TXT`: холодный вызов 6,7 мс → 1,6 мс, хвост 8 с → 2,4 мс |
| `WithIdleTimeout(0)` | канал без вызовов закрывался через полчаса, а кодера спрашивают редко — к каждому вызову он успевал остыть заново |
| `conn.Connect()` при старте | первый вызов не платит за знакомство: 0,34 мс вместо 6,7 мс |

**Рекомендуемый бюджет клиента — 500 мс** (`WAF_<X>_GEO_TIMEOUT`, умолчание
с 12.09.2026; было 100 мс). Он отмерян не на работу кодера, а на дурную
минуту сети: ждать здесь нечего, но промах — это молча несостоявшийся бан,
и экономить полсекунды раз на канал незачем. Ниже 200 мс не опускать.

## Запуск

```sh
cd geo
go test ./...
go run ./cmd/geo
```

По умолчанию читает `./data/country` и `./data/asn`. Для проверки из
репозитория:

```sh
set WAF_GEO_COUNTRY=./testdata/country
set WAF_GEO_ASN=./testdata/asn
go run ./cmd/geo
```

```sh
curl "http://127.0.0.1:8092/lookup?addr=8.8.8.8"
curl "http://127.0.0.1:8092/lookup?addr=0.0.0.0/0"
curl -d '{"addrs":["8.8.8.8","1.1.1.0/24"]}' http://127.0.0.1:8092/lookup/batch
```

```sh
grpcurl -plaintext -d "{\"addr\":\"8.8.8.8\"}" 127.0.0.1:50051 geo.v1.Geo/Lookup
```

Переменные — [internal/config](internal/config/README.md).

Пульс присутствия — `WAF_STATUS.service.geo.<id>` каждые 4 с: сколько стран
и ASN в памяти, хеш копий выгрузки (`country_sha256`, `asn_sha256`) и `conf` —
ревизия документа `policy/geo` и исход (`ok`, `fetching`, `fetch_failed`).
Это не lookup и не healthcheck контейнера. Шина не обязана быть жива при
старте: кодер отдаёт ответы, пульс догонит.

## Данные

Путь — каталог, `.tsv` или `.mmdb`. Формат выбирается по тому, что лежит
на диске.

| Источник | Country | ASN |
| --- | --- | --- |
| Каталог | `<код>.txt` или `<код>/ranges.txt` | `<номер>.txt` или `<номер>/ranges.txt` |
| TSV | выгрузка контроллера: `code type address name` | то же, `code` — номер AS |
| MMDB | `GeoLite2-Country.mmdb` | `GeoLite2-ASN.mmdb` |

Текстовый файл — одна строка на префикс или точный адрес, `#` — комментарий.
`# name: United States` задаёт подпись. Код страны — ISO 3166-1 alpha-2
в нижнем регистре, как в контроллере.

Учебный набор в `testdata/` — то, что loadgen кладёт в `X-Forwarded-For`:
`ru` / AS12389 (`5.8.8.0/24`, `95.24.0.0/16`, `2a02:6b8::/32`),
`us` / AS15169 и AS13335 (`8.8.8.0/24`, `1.0.0.0/24`, `1.1.1.0/24`),
`jp` / AS2516 (`133.0.0.0/8`, `210.173.160.0/19`).
Частные сети и TEST-NET в набор не входят — кодер для них пустой.

Горячая перезагрузка: опрос отпечатка раз в `WAF_GEO_RELOAD_EVERY` и
`SIGHUP`. Ошибка чтения оставляет действующий снапшот.

## Выгрузка из панели

Источник у каждого вида свой: каталог из окружения или копия выгрузки,
загруженной в панель. Контроллер называет файл документом `policy/geo` в KV
`WAF_DESIRED`, и на каждую ревизию `internal/fetch` делает одно и то же:

| Шаг | Что | Если сорвалось |
| --- | --- | --- |
| Скачать | `GET <WAF_GEO_CONTROLLER_URL>/api/geo/files/<вид>` в `<вид>-*.part` | кодер на прежнем, повтор через 1 с … 30 с |
| Сверить | размер и `sha256` с документом | файл удаляется, повтор: у контроллера уже файл новее, документ на подходе |
| Назвать | `<вид>-<hex>.mmdb` в `WAF_GEO_FETCH_DIR` | — |
| Собрать | таблицы только этого вида; второй вид переезжает указателями | снимок прежний, копия удаляется |
| Подменить | один атомарный указатель, `gen` + 1 | — |
| Убрать | прежнюю копию, только теперь | каталог из окружения не трогается никогда |

Запросы, пришедшие до подмены, дорабатывают на своём снимке, пришедшие после —
на новом; промежуточного состояния, где страны новые, а ASN наполовину старые,
нет. Клиенты кодера сбрасывают кэши сами: новое поколение приходит в первом же
ответе.

При старте самая свежая целая копия (хеш сходится с именем) выигрывает у
каталога из окружения, прежние и недокачанные удаляются: кодер поднимается на
последней загрузке, не дожидаясь ни шины, ни контроллера. Копия, чей хеш
сошёлся, а разбор нет, — не повод падать: старт на каталоге, документ пришлёт
её заново.
